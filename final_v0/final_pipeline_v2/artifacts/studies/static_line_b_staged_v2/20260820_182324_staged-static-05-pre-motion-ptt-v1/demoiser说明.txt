Denoiser 为什么有 F1：
这里的 F1 不是 motion detector 的分类 F1。它是 denoise 后重新检测 PPG beats，并在消除 ECG–PPG 固定延迟后，与 ECG R-peak annotations 做一对一事件匹配得到的 beat-detection F1。
RMSE 只在连续且成功匹配的 interval 上计算。如果算法只保留少量容易匹配的 beats，RMSE 可能看起来很好；F1 会惩罚漏检和误检。因此现在：
PPI–RR RMSE 是主排序指标；
beat F1 是必要的覆盖率/错误检测保护指标和并列排序指标。

2. Threshold adaptation：应如何做
不能手动看 Frailty29 结果后移动 threshold 并将同一结果登记为正式成绩。正式流程应为“固定模型、仅在训练参与者上拟合一个标量 threshold”：
对于参与者 \(i\)、类别 \(y\)：
\[
c_{i,y}=\operatorname{median}\{p_{ij}:Y_{ij}=y\}
\]\[
C_y=\operatorname{median}_i(c_{i,y}),\qquad
\tau=\frac{C_0+C_1}{2}
\]用于 PTT 模型适配 Frailty29 时：
1. 完全冻结 PTT 模型和 scaler。
2. 对 Frailty29 生成概率，不重新训练网络。
3. 按 participant-grouped 5-fold：
   - 在四折参与者上计算 \(\tau_k\)；
   - 只对第五折应用 \(\tau_k\)；
   - 汇总五折 threshold-adapted OOF window/file 成绩。
4. 完成正式 OOF 评价后，才可用全部29人拟合一个部署 threshold。
5. 全29 threshold 对同一29人的 in-sample 成绩不能登记为正式性能。
论文中可把第3步登记为：
PTT-pretrained, target-domain threshold-adapted grouped-OOF evaluation

但不能称为 untouched external validation，也不能把它和原始 PTT threshold 的 frozen transfer 混为一项结果。
当前模型能否仅靠 threshold 恢复？
不能。
PTT→Frailty29 当前 threshold 为 0.4999995576，但 Frailty29 上：
- static 分数中位数：0.9999990463
- motion 分数中位数：0.9999990463
- window ROC AUC：0.5635
- file ROC AUC：0.5674
两个 participant-balanced class centres 完全相同，所以当前严格 midpoint 合同会拒绝生成 threshold。
即使违规地在全部29人上寻找最大 BA threshold，理论上也只有：
- window BA：约 0.5384
- file BA：约 0.5503
这说明不是简单 threshold 偏移，而是严重的目标域概率饱和和类别排序能力不足。Platt scaling、isotonic calibration 等单调校准也不能提高 AUC。
结论：
- 可保留原始 PTT→Frailty29 作为正式的失败型 frozen-transfer ablation。
- 不建议把 threshold-adapted PTT 模型作为 Stage05 SQI 正式路线。
- 如果以后仍做适配，只能作为独立的 fold-local threshold-adaptation ablation。
- 单个用全29人拟合的 threshold 不应放进 Stage05 的 held-out CV；否则 threshold 看过验证参与者的 activity labels。
